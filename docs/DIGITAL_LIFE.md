# Conway 距离数字生命的距离

Conway 当前是面向数字生命研究的自主 Agent 底座。已实现持续循环、工具调用、
文件记忆、目标文件与学习接口，但还没有证据表明它能长期可靠地适应环境、
持续提升能力或递归改进自身。不能用一个完成度百分比或“再等几年”描述这些缺口。

## 先明确研究目标

人工生命并不等于拥有大语言模型，也没有一个仅靠“可以复制自己”就满足的统一验收。
ISAL 对数字演化的介绍讨论了遗传、变异和选择，不同系统对显式自复制的要求也不同。
Conway 选择的方向更具体：能够在指定数字环境中持续活动，积累经验，适应变化，
并通过可验证的学习和改进增加能力。下面是本项目的工程研究标准，不是整个领域的定义。

| 能力 | 当前证据 | 缺口及下一种证据 |
|---|---|---|
| 感知与可靠行动 | 有 GUI/文件/Shell 接口；已做两款真实小模型检查 | 多步任务、坐标定位和格式仍失败；需要未见过的真实桌面任务与重复试验 |
| 长期自主与运行维护 | 单 loop、目标热读、空闲退避、停止、崩溃恢复 | 还缺跨小时/天的真实任务结果、恢复率、资源消耗与无进展比例 |
| 经验积累与迁移 | Markdown 记忆、完整日志、可选视觉轨迹 | 读到旧经验不等于学会；需证明相似新任务更好、无关任务不退化 |
| 持续学习 | 离线数据/训练入口和可选 feedback 接口 | 现有适配器不更新权重；需真实学习模型、保留集、旧能力保持与学习成本记录 |
| 遗传与演化实验 | 有版本和受限程序复制的组件测试 | 没有 Conway 自主完成的有效后代实验，也没有变异—选择—遗传的能力证据 |
| 递归改进与开放式发展 | 模型/代码可替换，有验收依据 | 需多轮由系统提出的有效改进、独立复验和新任务迁移；修改代码、重复复制或更改评分不算能力提升 |

开放式发展也不等于不断生成任务。Hughes 等人的研究以新颖性和可学习性讨论
open-endedness；本文将“有用的新能力能被验证并积累”作为研究方向，而非声称已实现。
持续学习还要同时看旧能力保持、前向/后向迁移及资源成本，不能只看一次新任务成功。

## v0.10 具体推进了什么

1. **先看结果再决策。** 决策上下文优先显示最新执行、错误或被抑制的动作。
   历史截图元数据和行动说明保留在审计日志，减少小模型每轮阅读的重复信息。
   干跑和不确定结果仍显式标记；目标、日志、记忆仍使用文件。
2. **减少无效重复。** 文件、Shell、MCP 的相同动作不会因屏幕上的时钟或其他
   无关变化而重新获得重复额度。GUI 动作仍可因画面变化重置计数。
   这只是有限的重复保护，不会判断所有任务进展，也不检测所有交替动作循环。
3. **比较能力得失。** 独立脚本读取同一套 workbench 验收报告，列出新增成功和
   丢失的旧能力，拒绝任务缺失、检查项不一致和自相矛盾的通过标签。

这些是人工开发的 harness 改进，不是 Conway 自主学习或递归进化的结果。
[真实权重复测记录](validation/2026-09-26-feedback-recheck.md)单独报告模型效果。

## 保持轻量的改进流程

默认仍为一个模型和一条行动循环。目标、经验、候选版本及验收报告通过文件衔接。
对比脚本在循环之外运行，不添加数据库、训练守护进程或模型群体管理器。

```sh
python scripts/compare_acceptance.py baseline-workbench.json candidate-workbench.json
```

输出给出任务得失、版本/模型标签、输入文件 SHA256。两份报告都含预算元数据时，
预算不同会拒绝比较；旧报告缺少该信息则明确标记为未核对，需查原始实验记录。
退出码 0 表示比较完成且没有
发现旧任务回退（也可能完全没有改善），2 表示发生回退，1 表示报告无效或不可比。
它不会启动模型、更新权重或切换版本。输入来自可信的独立验收过程是前提；此脚本
检查报告一致性，不能鉴别伪造的报告或证明输入模型身份。

比较模型时固定 harness、任务、推理设置和预算；比较 harness 时固定权重和运行时。
保留失败和基线，在未参与调试的任务上复验。对持续学习模型，先后测旧任务与新任务，
再统计遗忘及迁移。单次分数变化只能作为后续调查线索，不能作为学习或进化结论。

下一阶段优先达到“一个小模型能稳定完成并验证常见多步任务”，再做跨会话经验迁移、
长时间运行与真正的学习实验。复制部署研究可以并行作为独立的受限实验，但复制数量
不应当成为能力或生命程度的替代指标。
